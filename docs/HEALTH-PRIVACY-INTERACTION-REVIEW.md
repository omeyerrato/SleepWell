# Health Connect and Data/privacy interaction review

Source baseline: `2552adfda167764f1ab0b2e1ff133190216d8ac1`, reviewed 2026-10-27. This is a bounded source review and implementation change, not whole-app security acceptance. No phone, provider account, document provider, device output or CI execution was used in this review.

## Confirmed issues and fixes

| Interaction | Exact source evidence | Resulting change |
| --- | --- | --- |
| Keep local copy / allow hidden imports while Health Connect is unavailable | `HealthSleepJobs.Job.start` called `provider.access()` before every action, including `HealthSleepStore.resolve` and `allowHidden`, which only change local SQLite. A provider exception prevented the chosen local action. | Only inspections and manual sync query provider access. Local choices retain the existing epoch, pending-payload and local-fingerprint checks. Allowing hidden imports still reads no provider records until a later manual sync. |
| Return from permission settings during an active worker | `HealthConnectActivity.onResume` called `inspect`, but `Job.start` returned immediately when busy. The refresh request could be lost and the older grant snapshot retained. | Busy inspection requests coalesce into one follow-up inspection on the same serialized worker. Draining the worker includes that follow-up. A failed access inspection publishes unknown availability and empty grants instead of retaining a connected snapshot. A prior permission-denial notice clears when the refreshed selected grants are present. |
| Cancel/back/recreation with a confirmation callback still retained | Health conflict/hidden-import and history-deletion positive listeners dismissed the dialog and submitted work without checking whether that dialog remained open. Backup replacement checked review identity, which remains identical after cancelling its dialog. | Dismissed history confirmations are inert. Health and backup additionally require the current dialog and resumed, live owner; pause/back/destroy close their confirmation. Accepted work keeps its existing retained-worker semantics. These are callback ownership fixes; no external exploit is claimed. |
| Backup chooser action queued while leaving the screen | `BackupActivity.onCreate` posted an automatic chooser action; `choose` had no finishing/destroyed check. | `choose` rejects a closed owner. Existing picker result correlation, transient document access and reviewed replacement stay in place. |

## Verification and remaining limits

Existing methods were extended without adding any `@Test` methods:

- `HealthConnectFlowTest#selectedImportManualSyncReopenSourceAndConflictChoicePersist`: invoke a retained canceled provider-choice callback, verify the local edit/conflict remains, then keep the local copy with injected provider access unavailable and assert no access call.
- `HealthConnectFlowTest#providerAndPermissionPrerequisitesNeverReadSleepOrFakeConnected`: gate one injected permission inspection, request another while busy, revoke the injected grant, and assert the latest state wins; a failed inspection must clear the connected snapshot. No sleep reads/writes occur.
- `PrivacyHistoryFlowTest#confirmedEraseIsRetainedDbFirstAndPendingAudioRetriesWithoutDeletingNewHistory`: invoke the canceled deletion callback and assert the command remains INSPECT with the fixture record/file retained. Readiness text now matches the current actual privacy subtitle.
