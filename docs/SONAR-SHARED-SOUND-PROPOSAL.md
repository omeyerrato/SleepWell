# Shared contactless capture and optional sound analysis

This is an incremental analysis-only flow, not full parity with motion tracking's clips or anti-snoring cues. No physical hardware or native capture has been exercised for this change.

## Capture and conversion contract

The planned runtime uses the existing single 48 kHz mono PCM16 sonar AudioRecord. Explicit default-off consent belongs to the current visible manual-start ticket and cannot escalate on resume. Calibration, automatic starts and recurring starts do not acquire this consent. No second microphone, global recording preference mutation, WAV saving or anti-snoring output is part of this flow.

`SonarDownsampler` is an original causal 193-tap, normalized Blackman–Harris low-pass FIR (7 kHz cutoff) before decimation by three. It waits for 193 actual samples, retains exact filter state across blocks and never pads a start, gap or EOF with invented input. The 96-input-sample (2 ms) group delay is subtracted from the output's original BOOTTIME sample timestamp. Its output is exactly 16 kHz, with bounded input blocks and a 36-hour counter limit. Discontinuity is rejected before consuming input. Its digital synthetic tests are not measured acoustic suppression or evidence that the phone can hear any particular sleeper.

The independent `SonarSoundPipeline`/`SonarSoundWorker` now implement a bounded nonblocking 64-block copied PCM queue, model ownership on one worker, original capture time, invalid/gap segment fences and asynchronous close acknowledgement. They do not interrupt an in-flight model call or claim it has closed before acknowledgement. Queue rejection is an explicit error. Integration with manual tracking and ordered SQLite updates remains a separate step. A zero classifier event count does not demonstrate that sound analysis was off, and a positive event is only a model estimate. Existing model scores, category thresholds and grouping behavior stay unchanged.

Primary references: [AudioRecord BOOTTIME timestamps](https://developer.android.com/reference/android/media/AudioRecord), [Android audio-input sharing](https://developer.android.com/media/platform/sharing-audio-input), [YAMNet input pipeline](https://github.com/tensorflow/models/blob/master/research/audioset/yamnet/inference.py), and [low-pass-before-decimation rationale](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.resample_poly.html). The custom implementation intentionally does not use boundary zero padding.

## Historical evidence contract (schema 9 / portable format 6)

`sessions.sound_analysis TEXT NOT NULL DEFAULT ''` is additive. An empty value means **unknown**, including every pre-existing recording and imports in formats 1–5. New explicitly manual sonar recordings default to an encoded **off** state, or **pending** only when the caller supplies actual per-run consent. Motion and manual history entries remain unknown until they have their own explicit provenance implementation; their existing behavior is preserved.

The separate `SoundAnalysisProvenance` version-one codec carries exactly `version`, Boolean `requested`, `state`, whole nonnegative `frames`, and allowlisted `issue`. `frames` counts actual successful full model inferences, never sound events. States are `off`, `pending`, `active`, `complete`, `insufficient`, `interrupted`, and `error`. Off has no consent/count/issue; complete requires at least one actual inference; insufficient has zero. Only error/interrupted admit an allowlisted issue. No arbitrary exception, audio path or capture command is stored.

`Store.soundAnalysisCheckpoint(id, encoded)` requires the same still-open sonar owner, immutable requested consent, monotonic actual count and a count that fits already-durable capture time. It never invents extra active time. An ordered caller must first flush the capture checkpoint covering those frames. `Store.end(id, interrupted, active, now, encoded)` atomically validates and commits the final state with the actual end (including pause closure), rolling both back on failure. Complete/insufficient cannot be published before this final transaction. An error may be durably published while sonar continues without analysis. Recovery and unfinished portable restore convert pending/active to interrupted, keeping the last durable actual count. The immutable sonar engineering `sensor_config` is unchanged.

Format 6 validates evidence before replacement; malformed types, states, consent, excessive counts, missing fields and non-sonar ownership reject the whole import. Existing format 1–5 semantics, inactive imported alarms, sound corrections, NULL imported clip links, all other session/sensor fields and eight-MiB bounds remain unchanged. Both `Records.csv` and the actual streaming `BackupDocuments.csv` append `sound_analysis`; projection, edit copies and goal aggregation preserve the raw evidence. No metadata read grants capture permission.

## Evidence and limits

Host Java/JUnit: eight synthetic FIR tests, five immutable status tests and nine fake-model pipeline tests and six bounded-worker tests pass (28 host tests total). Android `SharedSoundProvenanceStorageTest` is authored for twelve isolated private-database methods: typed all-table 8→9 migration, default/legacy handling, zero-event/error roundtrip, old imports, malformed rejection, owner/count fencing, final transaction rollback, recovery, guarded restore rollback, both CSV paths, invalid admission, and recovery rollback after an injected pause closure. Debug and native APK compilation, 47 focused pure tests and lint (zero errors, 94 warnings; none in the owned metadata/DSP files) passed locally. The twelve native storage methods have **not executed** at authoring time. There are no claimed UI screenshots, native classifier results, hardware performance measurements, clips or anti-snoring outputs from this metadata/DSP step.
