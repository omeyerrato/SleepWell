# Mirror text and private dream diary

F111 increment adds two real ordered task types. Mirror text has 1–6 rounds. Each occurrence/unit derives a stable phrase from its nonce and round, renders the actual native phrase horizontally mirrored, and requires the complete normally typed phrase including digits. It is an engagement task, not an authentication mechanism; accessibility services can expose the underlying text. The phrase/input survive recreation, while old occurrence/unit callbacks cannot advance the current routine.

Dream journal is one unit. Its saved minimum is 40/80/120/160/240 letter-or-digit code points, with at least 8 words of two or more characters and 5 distinct words. Unicode/Arabic text is supported. Repeated single words, emoji-only and short entries do not pass. This is an explicit engagement heuristic; it cannot judge meaning or whether a dream is true. Text is bounded at 5,000 characters. The journal entry must commit before the routine advances; real write failures retain the task and an error. No counter/button-only completion exists.

A retained worker captures only application context/database factory and checks current alarm occurrence/unit before admission and immediately before commit. The existing advance(run,unit) fence is retained. UI callbacks close on pause/build/destroy; resumed/recreated views attach to the owned pending write. Hashed occurrence/unit ownership makes retry idempotent. The tiny last-check/commit/advance boundary cannot be atomic across independent SQLite and alarm preferences: an entry explicitly submitted just before an external stop may remain saved, while stale advancement is rejected. No Scheduler lock is held across storage work. Manual diary creation also uses a stable request ID, preventing duplicate entries after ambiguous completion. A committed entry/close failure is disclosed as saved with confirmation needing retry.

The separate private `sleepwell-diary.db` has its own schema1. Main sleep schema10, tags, Health Connect metadata and portable sleep format7 are unchanged. Diary supports 200-entry pages, explicit create/edit, stale-revision delete, and bounded4MiB UTF8 JSON export through a user-chosen document provider. Export excludes occurrence ownership. Cancellation never promises to undo provider bytes already written; partial output is disclosed. Main sleep backups exclude diary, stated in the diary/export UI. Entries can be deleted individually. No cloud/API/automatic sharing is added.

Dream diary is reachable from recorded Signals and from a completed silent journal preview. Root Report options should also link to private DiaryActivity so it is available without a saved night. Editor config exposes real rounds/minimum and explicit silent preview; saving an alarm does not write a diary entry or start any output. Preview submission of a journal entry deliberately saves to the same private diary and says so.
