# Alarm tone selection and quiet preview

Board03 now has three actual bundled tone rows, selected radio states, waveforms derived from their PCM, a separate alarm-volume slider, and a separate preview-volume panel. Extra loud and Gentle wake-up remain available through Alarm sound options. Built-in and My audio tabs stop the prior preview. Device alarm remains selectable under My audio, preserving existing settings. Unknown/default/external audio receives no invented waveform. Only Save alarm writes the user's alarm; picking a row or pressing Use changes the editor's draft. Leaving the editor without saving preserves the stored alarm.

Daybreak and Pulse asset bytes are unchanged. New Chime is original deterministic additive synthesis generated by tools/generate_alarm_chime.py under this repository's MIT license; no sampled/vendor audio is used. ## Output ownership and bounds

No MediaPlayer is created until the user explicitly presses a row Preview or Play preview. The preview controller has Play/Pause/Stop, generation-fenced callbacks, no automatic resume after backgrounding or recreation, and a separate0–25% digital-gain range. Alarm volume and Extra loud never change preview gain. Preview uses USAGE_MEDIA, AudioFocusRequest transient focus, pause-on-duck/loss, a non-exported noisy-audio receiver and lifecycle cleanup. It does not call AlarmAudioSink, acquire an alarm-volume lease, write any global stream volume, emit vibration, or access microphone/torch.

Preparation times out after8seconds. One decoder attempt per process may be active/closing across screen recreation; cancelled provider work cannot start later, and retries do not allocate parallel decoder attempts. After the first actual play, the total preview wall-time budget is20seconds, including paused time. The process lease is released only by actual worker cleanup, not UI close; a native release failure retains the gate and may require app restart. It also stops when an alarm, tracking or sleep-sound playback occupies the app's audio path. Cancellation and owner closure mute/release the native player and abandon focus on its worker. Android/provider implementations can delay synchronous descriptor/native work despite CancellationSignal; the attempt stays fenced and cannot later start. Digital gain is not a calibrated acoustic volume guarantee, and OS/media volume remains under the user's control.

## Audio documents

Import opens ACTION_OPEN_DOCUMENT/audio/*/CATEGORY_OPENABLE. Only a content URI with a provider authority and returned read/persistable grants is accepted. On a worker, the production source checks audio MIME, opens the explicitly granted descriptor, requires a declared/stat size up to32MiB (unknown-size provider pipes are rejected), verifies an audio MediaExtractor track and retains only read access. It never forwards a returned Intent or opens arbitrary file/network URIs. Native MediaPlayer still waits for explicit Play. External/default audio has no waveform because this change does not implement its actual full PCM decoding.

Cancel preserves the prior tone. Newly acquired but unaccepted persisted grants have discard cleanup off-main after a pinned SQLite check; preexisting grants and URIs still referenced by saved alarms or the pinned sleep-sound mixUri are preserved. The raw mixUri check/release uses the same SoundPreferences monitor as its import commit; unrelated corrupt mix fields are not loaded. Main completion must atomically accept before changing the draft; expired completions cannot select a released grant. If saved-reference storage cannot be inspected, cleanup preserves uncertain access rather than breaking another alarm. Grant release is best effort; an Android/provider failure may retain the authorization. Unsupported URI, unreadable/revoked/non-audio documents, missing picker, timeout and cancellation receive concise errors. UI import work is cancelled/fenced when paused, closed or recreated; the old draft cannot be changed by a late completion. At most one provider-import operation per process can remain blocked. Recreate preserves tone/alarm-volume/preview-volume/tab, while playback remains stopped. Persisted document grants cannot guarantee future availability if the file moves, is deleted, or its provider revokes access; a later preview reports failure. An explicitly accepted import retains its grant even if the user later cancels the unsaved editor; this is not general orphan-grant collection. Actual provider/device playback and OEM focus behavior remain unverified by fake-output tests.
