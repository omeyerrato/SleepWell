# Quantitative tags and saved-record associations

F130 increment adds real optional per-record quantities and global rename/delete. Existing string tags stay unchanged. The existing `record_edits.tags` JSON column also accepts strict `{name,quantity,unit}` entries. Values must be finite 0–1,000,000; unit is user-entered, at most 24 characters, with no inferred conversion. Decimal keyboards including Arabic Indic digits are accepted; grouping, exponent and nondecimal numeric symbols are rejected. Bare tags remain unknown quantity, never zero. No database or portable-format version bump is required; current format7 and both CSV paths preserve the typed value. Old format/string-tag imports remain supported. Earlier app versions that only support string tags cannot read quantitative entries.

Edit sleep → Set tag quantity opens a draft dialog. Use quantity changes only the draft; Cancel does not. Pending amount/unit and the chosen quantity survive recreation. Save changes uses the existing atomic/stale-checked record-save contract. Removing a tag removes its quantity. Existing remove-chip behavior is preserved. Manage saved tags is reachable from Editor, and Compare & manage tags is reachable from recorded signals when saved tags exist.

The management screen computes a read-only snapshot on its retained worker. It compares actual effective closed main-record durations with/without the selected tag, displays real sample/source counts, and excludes explicit naps, future/empty periods and all overlapping ambiguous records. Missing dates create no records or zero-duration samples. This is a per-record comparison, not a clinical nightly score. Quantities are grouped by exact user unit. Each group shows real range/count and Pearson association with its paired actual duration only with at least 3 samples and nonzero quantity and duration variance. No causal, dose or medical recommendation is made; confounding and selection effects remain.

Rename/delete captures the actual matching-record signature and checks it again inside one transaction. New/deleted/edited affected records reject the action instead of overwriting. Rename collisions reject rather than merging/discarding quantities. Per-record revisions advance, so a previously open editor cannot resurrect old tags. A failure in a later write rolls back earlier updates. Raw sessions, sensor/audio/Health Connect evidence, notes and other tags remain untouched. Restoring a measured original can restore a tag in its original note; that limitation is disclosed in the delete confirmation.
