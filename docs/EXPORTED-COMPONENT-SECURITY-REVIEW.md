## Applied alignment and verification limits

IS04 is a sensitive-confirmation touch alignment change, medium priority. An incoming request still cannot bypass global opt-in, unlocked visibility, current recording identity, receipt deduplication or service admission. The added hook closes the concrete missing partial/mid-gesture rejection at its review UI; no real-world exploit or service admission bypass was demonstrated. It can reject benign overlays, with the existing helper's explanation. No permission, manifest, SDK, command format or feature changed.

```diff
 public final class IncomingAutomationActivity extends Activity {
+ private final SensitiveReviewTouches reviewTouches=new SensitiveReviewTouches();
+ @Override public boolean dispatchTouchEvent(android.view.MotionEvent event){return reviewTouches.dispatch(this,event,super::dispatchTouchEvent);}
```

The existing `obscuredNativeGesturesCancelAndRequireAFreshCleanDown` method now additionally launches an invalid-terminal IncomingAutomationActivity, installs an inert native Button and dispatches synthetic flags through its actual Activity hook. It neither enables incoming automation nor prepares receipts/grants/commands. There are still two security test methods; the new extension is pending execution. `git diff --check` passed. The earlier [three-method native pass](verification/2026-10-27-interaction-security-ci40505746079/README.md) predates this hook and covers only its explicitly recorded scope.

No additional concrete app-owned exported-path vulnerability was established in this bounded pass. Remaining review limits are the unresolved Nearby handler, full dependency internals/dynamic surfaces, cross-UID permission/grant enforcement, actual hostile overlays, real OS permission controllers and physical-device lifecycle/output behavior.
