# Contactless sonar: proposed first vertical flow

Research/source baseline: d43f480. Proposal only; no production implementation, build, speaker output, microphone capture or device actions have run. Board06 was visually inspected. Existing motion tracking, saved data and recurring preferences must remain unchanged.

## Evidence and current integration constraints

Sleep as Android describes active speaker/microphone echo sensing near the upper audible band, nightstand placement toward the body, hardware-dependent support and no headphones. This is a distinct sensor, not microphone loudness. Its feature claims do not validate SleepWell. [Sensor docs](https://sleep.urbandroid.org/docs/sleep/sensors.html), [sonar FAQ](https://www.sleep.urbandroid.org/docs/faqs/sonar_faq.html).

The University of Washington paper demonstrates frequency-modulated acoustic sensing using smartphone speakers and microphones. It establishes feasibility and a useful signal-processing reference, not accuracy for this app or arbitrary phones. Implement original DSP code; do not import vendor/app code or claim its clinical results. [Primary paper](https://modernmobile.cs.washington.edu/docs/apneaapp.pdf).

Current TrackingActivity disables sonar. TrackingService.collect always registers the accelerometer; its minute/smart-wake path interprets acceleration RMS using MotionProfile. NoiseRecorder separately owns 16kHz MIC capture. A second independent AudioRecord is therefore unsuitable. No sonar value may silently become an acceleration threshold input. Recurring automatic starts must remain movement-only.

## Proposed deliverable and ownership

First complete owned flow: Tracking setup hook (parent later) -> ContactlessSetupActivity -> explicit Test signal -> real bounded duplex capture -> measured echo-change graph and honest quality/error -> explicit Use sonar saves a new private SonarSettings profile -> reopen/cancel persistence. This first commit is real hardware-adapter/DSP/calibration functionality, but is not overnight sonar acceptance. The next integration uses the same runtime/sink after a visible manual Start establishes microphone FGS, with Pause/Stop/Resume and sensor-labelled saved measurements. Parent must coordinate that shared hook after jetlag work; no Tracking*, manifest, Main, CI, Store or Backup edits in this author's first change.

Own new SonarConfig, SonarSettings, SonarCapabilities, SonarPolicy, SonarChirp, SonarAlignment, SonarDsp, SonarAudio, SonarRuntime, SonarFrame and ContactlessSetupActivity plus focused tests/docs. Root owns manifest/entry hook and coordinates later session-storage/report contract. Until that hook exists, the sensor preference must not cause existing motion Start or recurring entry to open audio automatically.

## Exact starting signal/DSP contract

- Mono PCM16, 48000Hz client rate. Original phase-continuous linear FMCW chirps, 18.5-20kHz, 1920 samples/40ms; 770 cycles over a chirp avoids a phase jump at its boundary. Initial/final amplitude ramps and a small digital gain are explicit; no claim that the waveform is inaudible on every phone.
- Original proposed gain: .05 default, bounded .01-.10; never change any global/media/alarm volume, take an alarm-volume lease, disable system sound enhancements, or auto-increase gain. Muted media is a visible user-action prerequisite. This is a software gain bound, not a measured sound-pressure guarantee.
- Align actual capture and transmit frames using advancing monotonic AudioRecord/AudioTrack timestamps and a bounded direct-path correlation check. Reject unavailable/unstable timing and missing direct reference; do not infer good signal from microphone amplitude. Recalibrate after any route/format discontinuity. Report no centimetre/range measurement to the user.
- Complex dechirp against the emitted reference, low-pass difference band, Hann-windowed range FFT; calibrate stationary leakage/multipath and exclude the direct-path guard region. Compare calibrated echo bins across frames; emit a bounded relative echo-change metric only when supported by current valid echo energy/timing. Missing/clipped/silenced/drifted samples yield null/gaps, never synthetic zero-motion evidence. Show at most five actual aggregate updates/second and a bounded 15-second history.
- Two-second stationary baseline followed by a bounded explicit movement check, total test <=20seconds. No valid off-direct echo/change -> signal unavailable/needs repositioning, not Signal ready. Thresholds are engineering quality gates to test, not calibrated sleep-stage/breath thresholds.
- Pure DSP fixtures: delayed emitted chirps plus controlled moving echo versus stationary direct leakage, unrelated audible noise, silence, clipping, wrong chirp/rate, chunk boundaries, gaps and clock drift. Verify no ready/motion success from direct leakage alone. Synthetic PCM validates algorithms, not a phone/bed/person.

## Runtime interfaces (proposed)

`SonarConfig`: immutable versioned rate/band/chirp/gain/charging config; strict codec, no legacy key reuse.

`SonarFrame`: monotonic interval, nullable relative movement, quality enum, echo SNR/correlation/clipping diagnostics and algorithm id; no PCM, sleep stage, respiratory diagnosis or fabricated wave.

`SonarAudio.Port`: capability/route snapshots; explicit open/read/write/stop/close; actual input/output device ids, silencing/format/route callback and timestamp data. Production adapter is separate from a fake; tests never instantiate native capture/output.

`SonarRuntime`: explicit start(config, Listener) from an authorized visible calibration entry or later microphone-FGS owner, cancel(reason) returning immediately, async Closed notification, immutable state snapshots and generation fences. Listener callbacks are posted to main; a feature Sink can later persist actual intervals off main. A process-wide identity lease stays owned until actual IO cleanup completes; cancel never admits unlimited blocked workers.

`SonarPolicy`: pure state/admission decisions for grant, visible/FGS owner, charging, occupation, actual built-in routes, focus, silence, timing and sensor format. All unsafe/lost prerequisites close or suppress capture/emission; no fallback to motion.

## Permission, routing, lifecycle and error behavior

Use existing RECORD_AUDIO with contextual rationale, cancel, first denial and permanent-denial/settings states. Recheck live grants before opening and catch revocation. Calibration begins only on explicit Test while visible. Microphone FGS must be established by visible manual tracking before any night capture; no background/boot/recurring sonar admission. [FGS microphone limits](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone).

Inspect nullable near-ultrasound speaker/mic capability properties. Explicit unsupported values block the test; unknown values are visibly unverified and require successful calibration. Prefer UNPROCESSED when reported supported; otherwise VOICE_RECOGNITION with calibration rejection on unusable processed input. Client format/route/property hints alone do not prove an acoustic path. [AudioManager capability properties](https://developer.android.com/reference/android/media/AudioManager), [Android near-ultrasound requirements](https://android.googlesource.com/platform/compatibility/cdd/+/refs/heads/main/7_hardware-compatibility/7_8_audio.md).

Require charging, normal audio mode, no alarm/tracking/other in-app audio owner, and no external/headphone routes. Request ordinary audio focus without forcing it. Start the output muted with zero PCM to establish an actual built-in speaker route; require the actual built-in microphone too. Only then allow bounded chirps. Preference is not routing proof: recheck actual routes while active, use route callbacks and API36 multi-route queries, mute/stop on loss, focus loss, capture silencing, unplug or audio errors. Public callbacks cannot guarantee zero transient sound during an OS reroute; do not claim perfect routing. [AudioRouting](https://developer.android.com/reference/android/media/AudioRouting), [capture silencing/configuration](https://developer.android.com/media/platform/sharing-audio-input).

Construction, reads, writes, DSP and release run on bounded worker(s), never component lifecycle/main thread. Use finite queues, nonblocking PCM IO and monotonic no-progress deadlines; main cancels without waiting/joining. Release/mute/stop all native objects/listeners/focus in worker finally; reject new audio admission until the original owner actually closes. Activity pause/rotation/back cancels calibration, not background-continuing test output. Reopen requires explicit Test; a saved config never auto-starts capture. [AudioRecord nonblocking IO](https://developer.android.com/reference/android/media/AudioRecord#READ_NON_BLOCKING), [playback timestamp warmup](https://developer.android.com/reference/android/media/AudioTrack#getTimestamp(android.media.AudioTimestamp)).

Initially sonar owns the mic exclusively: sound clips, YAMNet, sleep sounds and anti-snore output are off for this sensor with visible explanation; do not start NoiseRecorder concurrently or mutate their saved preferences. Later shared low-pass/anti-alias downsampling of the same PCM could feed 16k analysis, after independent evidence and ownership review.

## Proposed per-night persistence and portable contract (root approval required)

Choose additive schema8 plus portable format5, rather than invent a new value in the existing strict source enum. No production schema edits are made in this proposal.

- Add `sessions.sensor TEXT NOT NULL DEFAULT 'unspecified'`, `sessions.sensor_config TEXT NOT NULL DEFAULT ''`, and nullable `epochs.signal_quality TEXT`. Existing raw rows/measurements/edits remain unchanged. Source stays tracked/manual/legacy. Existing old sessions are honestly unspecified; new explicit movement starts store accelerometer; new manual entries store none; new sonar starts store sonar_fmcw_v1. Keep `begin()` backward compatible and add an explicit immutable sensor/config entry for the later root hook.
- Sonar config is a small strictly validated versioned JSON object (algorithm, client rate, band/chirp, digital gain and capture source); it is metadata, never instructions or arbitrary file/network paths. Existing movement inference stays gated to actual motion runs and keeps its old thresholds. Sonar never enters MotionProfile, auto-stillness, Naps.movement or early Scheduler smart wake in this first implementation.
- Persist actual five-second contiguous aggregate intervals on the storage worker. A valid stationary echo can yield a measured zero; invalid/no-echo/clipped/timing intervals store movement NULL plus an explicit quality code, not zero. Preserve each measured start/end and quality; never average across gaps. Null intervals still checkpoint the recording timeline durably, so existing recovery sees their endpoint even after a signal failure. Save interruption/pause/end atomically through the parent storage adapter; no fake continued capture after native close.
- Reports/live/history say Contactless movement / Relative echo change for sonar and show loss-of-signal gaps; accelerometer remains Phone movement with unchanged data. Do not compare scalar magnitudes or reuse physical thresholds across sensors. Graphs use actual valid sample intervals, not filled/interpolated coverage or fake stages. Recorded time remains recording time; unavailable stages remain explicit.
- Format5 exports/validates/restores sensor/config and nullable per-epoch quality, while formats1-4 continue restoring unchanged with unspecified/none provenance and no quality. Strict allowlists, finite numeric/type/range/config-size validation, valid session linkage and raw-bound checks apply. Preserve the exact existing 8MiB whole-document limit: oversized output is an explicit error, never omitted evidence. Imported sonar stays a historical record and never starts capture. Existing clip/label/favorite metadata and all raw old rows must round-trip unchanged. Three added columns use existing epoch/session deletion paths; no hidden extra database/table escapes history deletion.
- Add meaningful migration7->8 and legacy1/2/3/4/new5 restore tests, sonar quality/gap roundtrip with edits and unchanged legacy rows, malformed config/quality rollback and interrupted final-null-epoch recovery checks. Root coordinates Store/Backup/RecordEntry/report changes after jetlag shared hooks; this author can supply the strict SonarConfig/quality codecs and new runtime sink contract without editing shared files first.

## Bounded source responsiveness audit

ANR risk: yes (HIGH), in the existing shared Tracking entry/storage path; no new production code exists yet.

- TrackingActivity.onCreate -> Store.recoverInterrupted (TrackingActivity:22) performs SQLite reads/writes on the Activity main-thread lifecycle. TrackingService.onStartCommand -> beginRecording (Service:60,64-67) opens SQLite/begins recovery and inserts a session synchronously on the Service main thread. These APIs can block on storage/SQLite locking; the file owns the synchronous call sites. Do not add sonar construction/calibration/FFT/provider work to them. Parent-owned integration should establish foreground state promptly and use ordered storage work with durable admission fences.
- Handler created with main Looper (Service:21) schedules minuteTick -> minute -> flush -> Store.checkpoint (Service:128-139): synchronous SQLite transaction on main is a separate hot-path storage blocking candidate. New five-second sonar writes must not inherit this path; provide an ordered worker sink instead.
- Dismissed: NoiseRecorder.read/capture runs on its explicitly named audio thread, not main. NoiseRecorder.close joins that thread, but TrackingService.closeAudio dispatches it through closer.execute (141-142); no main-thread join is proven. Prefs.put uses apply, not synchronous commit. No off-main attached-View mutation was found in these reviewed paths; new runtime callbacks must remain main-dispatched.

## Acceptance boundaries

Pure tests exercise real generated PCM/DSP and state ownership. Include delayed close, route lost before unmute/during output, capture silenced, partial read/write, dead object, stalled IO, charging loss and stale callback/owner cases.
