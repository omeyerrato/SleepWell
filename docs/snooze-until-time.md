# Exact clock snooze

When the existing per-alarm Choose duration each time option is enabled, the on-screen Snooze menu adds Until…. It opens the same SleepWell-owned clock controls with an explicit **Today, date and time zone** review. This version deliberately supports today only. An earlier clock never silently becomes tomorrow. At midnight or during skipped/repeated daylight-saving times, the existing relative-duration options remain available.

Confirmation selects an exact epoch deadline at the chosen clock minute, not a rounded number of minutes from now. It must be strictly later than confirmation and within the existing current per-press maximum, including shrinking snoozes and the60-minute cap. Invalid, past, repeated/skipped or excessive choices remain open with an inline error. The shared model checks occurrence, snooze count, enabled option, full active-alarm metadata revision, current settings, foreground ownership, time zone and wall/elapsed drift. The real consumer rechecks within Scheduler's ownership lock immediately before passing the exact target to Scheduler.at. Failure does not stop the alarm or mark a challenge complete.

Cancel, owner pause, recreation and destruction revoke the clock offer. It is never restored or confirmed automatically. Relative choices, flip snooze, hardware keys, default alarms, counts, challenge completion and wake-up checks retain their existing paths. No new schema, dependency, alarm metadata or backup format is introduced. Existing chooseSnooze JSON remains the opt-in switch.

Coverage includes exact seconds, bounds/shrinking, stale settings/count/revision, owner/focus, wall jumps/rollback, time zone, DST gap/overlap, midnight, cancel/one-use and scheduling denial.
