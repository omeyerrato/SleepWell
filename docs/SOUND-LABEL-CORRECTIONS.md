# User corrections of sound-event labels

F124 adds a user overlay to an ended night's saved sound estimate. Tap its label/tag control in Sound events or Favorites, choose a label, then Save label. Cancel leaves storage unchanged. Choose Use original estimate and Save to reset. Saved user choices display `Your label`; the original model category and score remain visible in the selector. This does not improve or retrain the model, change a WAV, relabel neighboring intervals, or trigger a snoring cue.

## Storage and consistency

Schema7 adds nullable `sound_events.user_category` and integer `label_revision` default0. Existing `category`, `score`, `model`, interval, WAV link and independent event/recording favorites remain original. The effective display/filter/count category is `COALESCE(user_category,category)`. The report distinguishes counts that include user choices. Cough, crying and laughter remain grouped under Other in the existing compact filters; offering a manual choice makes no automatic recognition claim. The broad automatic-category candidate remains partial.

Each correction or reset increments a per-event revision, independently of the wall clock. Compare-and-set checks the revision and previous user category, original event identity/score/link, and the current edited record revision/bounds in one SQLite transaction. ABA (choose another label then reset) cannot revive an old draft. A deleted event, changed interval, changed link or trimmed night must be reopened. Counters at the largest exact portable JSON integer (2^53-1) reject before any SQLite update; this avoids silent precision loss in the existing JSONObject storage projection or INTEGER→REAL promotion. Reset retains its revision rather than erasing concurrency history.

The selector retains one immutable, factory-pinned background operation across Activity recreation. Draft, busy and failure states survive rotation; choices/Save/Cancel/back are disabled during an accepted save, and there is no autoplay. After process death an uncertain old draft may be rejected and must be reopened; no automatic mutation retry occurs. A Save already accepted by the worker may finish if the app is backgrounded or its screen is destroyed. No worker retains the Activity.

A missing/deleted WAV does not erase its estimate or label: the existing no-audio/unavailable state remains, with no fabricated waveform or Play control. Label correction itself does not require recording playback. Legacy unclassified standalone WAV rows cannot acquire a fabricated classifier estimate through this feature.

## Portable backup and archive

Backup format4 adds ended-session sound-event metadata, including original category/score/model/timing, event favorite, nullable user category and revision. It intentionally excludes clip IDs, WAV paths and bytes, so restore produces analysis-only events. Portable validation rejects unknown keys, duplicate IDs, unknown/unfinished/manual sessions, unexplained intervals outside raw session bounds, wrong JSON types, non-finite/out-of-range scores, invalid categories/revisions/favorites and empty/oversized model identity. Sound metadata is bounded to100,000events and8MiB of UTF-8 JSON. The complete pretty-printed portable file is separately bounded to8MiB, matching the existing importer; an oversized backup errors before provider output instead of exporting an unreadable file. Formats1–3 restore with their old behavior; those formats never contained sound events. Active-session events are excluded until the session ends. WAV export remains the separate explicit archive flow.

Crash recovery now considers valid durable sound-event endpoints as last-observation evidence, in addition to epochs and pauses, within the existing36hour metadata bound. It does not invent active_ms, motion samples or PCM. For already closed interrupted records whose estimates extend beyond the recovered end, portable metadata explicitly uses interval_scope=interrupted_tail and retains both the original raw night end and complete original event interval on import. This is permitted only for interrupted=1, within36hours of raw start; otherwise export/validation reports an error. Normal intervals use raw_session, and forged or mismatched scopes reject before replacing data. No event is silently omitted or clamped. Playback/normal visible-period checks remain unchanged; preserving a tail is not authorization to play outside the edited window.

Night ZIP metadata retains original fields, adds effective_category and label_source (`user`/`model`), and includes the overlay/revision. A label change between plan and staging invalidates the plan before provider output. An already staged immutable archive remains a point-in-time snapshot. Its recording hashes and bytes stay unchanged.
