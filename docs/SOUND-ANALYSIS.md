# Local sleep-sound estimates

This implementation adds a genuine on-device YAMNet classifier, not an amplitude-to-snoring rule. It is a general sound model, not a validated sleep monitor or a calibrated probability estimator. Speech can come from television or another person; it does not establish that the sleeper talked. Snoring estimates can be wrong. No anti-snoring output is enabled by this work.

## Actual path

The existing user-enabled microphone capture remains 16 kHz mono PCM16. A fixed 15,600-sample float window (PCM16 / 32768) is sent to the bundled mobile model on the same capture worker. Model creation, warm-up, inference, buffer reuse and destruction all run there. CPU only is intentional for compatibility and avoids pretending a GPU fallback was exercised. There is no model-download button or network dependency.

A snoring estimate requires Snoring to beat all 520 alternatives, score >=0.60 and margin >=0.15. Speech needs >=0.65 with the same margin. Dominant silence is ignored; uncertain recognized sounds retain Other sound. Scores are uncalibrated model scores, not percentages of certainty. Two consecutive matching 0.975-second windows are required before an event is stored. Events split after ten windows; incomplete PCM tails and isolated positive windows are discarded on stop/pause. At most 3,600 metadata events are retained per tracked session, with the existing 60 WAV budget separate and shared across microphone restarts. Thresholds are conservative engineering defaults, not thresholds calibrated on clinical bedroom recordings.

SQLite schema5 adds sound_events and clip metadata columns without rewriting old alarms, sessions, epochs or WAV rows. Existing clips default to noise/score0; no retroactive labels are invented. Analysis-only mode persists events without saving any audio. The existing energy-triggered WAV path now links an event only when the entire estimated interval is contained in an actual saved recording; no event implies a recording unless such a clip exists. Real PCM duration is stored instead of assuming exactly10 seconds. Clip deletion/retention nulls event links, preventing SQLite row-id reuse from connecting an event to unrelated audio. Clip playback stays in Recorded signals. Favorites, a player that seeks directly to a classified interval and the complete board07 player design remain incomplete.

The Sound events screen is reachable from Recorded signals and displays actual timestamps, durations and category filters. Empty/loading/storage-error states are explicit. Current layout is partial board07 fidelity; screenshot review is still required before acceptance.

Model initialization/inference failure disables labels for that microphone instance and records analysisError; measured room amplitude and optional WAV capture continue. Stop still joins capture before the database closes. A failure to store events is surfaced rather than silently claimed as success. Erasing a night/history or restoring a backup also clears its event metadata. Portable backup format3 still excludes WAVs and sound-event metadata; this limitation is explicit and requires a future portable-audio backup flow.

## Evidence and limits

Pure tests cover all-label dominance, score/margin rejection, malformed outputs, transient false positives, duration grouping, PCM chunk boundaries/normalization, no incomplete-window padding, initialization/inference fallback, no work after close, and shared metadata/clip budgets. Native tests perform actual CPU inference on deterministic silence, sine and white-noise tensors and persist/reopen/delete an analysis-only fixture in a uniquely named database. Synthetic negatives check installation/false-positive regressions; they do not validate human snoring or speech accuracy. Three public CC0 human-audio previews are now included in the instrumentation-test APK: two uploader-labeled snoring recordings and a conversation/crowd distractor. Their source pages, exact preview/PCM hashes and decoding contract are retained under third_party/audio-fixtures. They are a compatibility/regression sample, not a calibrated bedroom evaluation set. SoundClassifierFixtureEvaluationTest writes actual per-window YAMNet scores and grouped event output to analysis-human-fixture-evaluation.json before checking basic positive-class response and the speech distractor. The stricter event-policy yield is reported separately from the lower installation-regression score threshold. The same real PCM is also fed in1024-sample chunks through the production SoundAnalysisStream and grouped events are inserted into an isolated Store, reopened and counted; acceptance requires at least one persisted snoring event across the two independent snoring fixtures and one persisted speech event from the conversation fixture. Production thresholds are unchanged; a zero-event result fails this gate. Native evaluation remains pending until CI runs this new class.

No physical microphone, playback, alarm, flashlight or vibration was exercised for this change. 185 local pure tests passed and debug/application-test APK builds passed. Native fixture tests have not run yet and must pass on the CI emulator before this feature is reported verified. The older AGP8.12 bundled lint analyzer prints an incompatible LiteRT Kotlin2.4 metadata diagnostic despite a green task. Running with the documented independent lint override `-Pandroid.experimental.lint.version=9.4.1` resolves that diagnostic: full analysis succeeds with zero errors/71 warnings. This does not change the app language, AGP or runtime inference. Integration should retain the compatible lint override. Background battery cost, long-night capture continuity, positive-class accuracy and real-phone inference latency remain unverified.

Primary references: [mobile model card](https://www.kaggle.com/models/google/yamnet/tfLite/classification-tflite/1), [TensorFlow model installation tests](https://github.com/tensorflow/models/blob/master/research/audioset/yamnet/yamnet_test.py), [LiteRT CompiledModel](https://ai.google.dev/edge/litert/android).

Automatic recording can supply an immutable per-run saveClips override through the NoiseRecorder overload; manual recordings retain the existing live save-clips preference. The constructor does not itself grant microphone consent or start a foreground service.

## Optional snoring cues (source, actual output unverified)

Snoring cues are off by default. The native settings screen saves Sound/Vibration/Both, intensity, one to three repeats and sensitivity. It requires microphone permission plus an enabled next-recording microphone setting, but never starts recording or emits a preview when saving. Existing automatic-recording microphone consent remains per-run and independent.

Only confirmed two-window snoring estimates can request a cue; speech and Other sound cannot. Low/Medium/High sensitivity uses minimum uncalibrated model score 0.85/0.75/0.60. Cues wait at least two minutes apart and stop after 30 requests per tracked session, with the budget shared across microphone restarts. Turning cues off prevents new requests. Pausing/stopping tracking cancels pending output work.

The production adapter lazily creates an output worker only after an enabled eligible estimate. Sound uses short ToneGenerator beeps at media-stream gain 10/20/35 without touching global stream volume; silent media stays silent. Vibration uses 60/120/200ms pulses at 40/80/140 amplitude, subject to device support. There is no alarm-volume escalation. Outputs are suppressed while an alarm is ringing; cleanup does not cancel the app's alarm vibration when that ringing flag is set. This is best effort across shared Android audio/vibration resources, not exclusive ownership.

Six pure tests cover opt-in/no allocations, category/sensitivity, cooldown/sessioncap, closure and output-init failure. SnoreCueSettingsNativeTest exercises settings with a fake output only and restores preferences; its CI-only permission grant belongs to the disposable emulator, never a personal phone. Actual cue hardware behavior, anti-snoring effectiveness and bedtime battery cost remain unverified.
