# Manual backup export receipt: backend and private document journey

This increment adds durable, per-kind completion receipts for the existing manual JSON-backup / records-CSV document flow. It does not yet wire a Last export row into PrivacyScreen or MainActivity; that UI hook is owned by a following integration. Existing current-session operation state and errors retain precedence.

A receipt is eligible only after BackupDocuments.write returns from preparing, writing, flushing and closing its output, and BackupJob accepts that still-current generation as DONE. The write/flush/close contract in BackupDocuments is unchanged. Chooser/open/cancel/import/review/failure paths do not notify the receipt writer. A cancellation before the DONE gate discards receipt eligibility even if the provider eventually returns. An operation already accepted as DONE remains a completed export; a later selection/cancel cannot undo that historical fact.

Receipt preference persistence runs on the existing pinned backup worker, after the nonblocking UI completion gate. Failure leaves the actual export DONE, with separate receiptStatus=UNAVAILABLE and receiptWarning; the document is not relabelled as a failed write and no duplicate export is requested. While persistence is pending, receiptStatus=PENDING is explicit. A later successful closed export can save a new receipt and clear the warning. No claim of a provider's remote durability/readback is made beyond its existing successful write/flush/close contract.

JSON and CSV have independent typed keys, so a CSV success cannot appear as the latest full JSON backup. No URI or exported content is retained. The dedicated local private preference file `manual-export-receipts` holds only versioned JSON/CSV completion timestamps and is excluded from the existing database/settings backups. Reads do not save defaults. Absence is NOT_RECORDED / **Not recorded**, not proof of Never: older app versions could export without a receipt. Malformed/unreadable storage is UNAVAILABLE. Store schema and backup format are unchanged.

API: `BackupJobs.receipts(context, records)` pins the job's BackupExportReceipt.Scope without preference I/O. The page's owned worker calls `scope.read(BackupExportReceipt.Kind.JSON)` for JSON backup or CSV separately. Read exposes status, kind, completedAt epoch milliseconds and problem; `read.format(zoneId, locale)` is a pure formatter with full local date/time and explicit zone ID. Factory and clock ownership are pinned per retained job; test fixtures use private preferences and fixed clock, never the production receipt store. The old three-argument BackupJob constructor keeps its existing no-receipt behavior for genuinely independent fake work.
